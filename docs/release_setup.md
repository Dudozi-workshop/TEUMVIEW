# Android release setup

## Current verified baseline
- Android debug build, Flutter analyze and Flutter tests passed in GitHub Actions run 45776962613.
- Artifact: teumview-debug-apk (debug build; not Play Store release).
- Provisional Android application ID generated by bootstrap: com.dudozi.teumview.
- Platform project is generated in CI by scripts/bootstrap_android.sh; generated android/ files are not currently committed.

## Before OAuth verification
1. Confirm final application ID. Current provisional value: com.dudozi.teumview.
2. Enable Google Calendar API in Google Cloud.
3. Configure OAuth consent screen and add Calendar readonly scope.
4. Create Android OAuth client for the final application ID and SHA-1 fingerprints for debug and release signing certificates.
5. If required by google_sign_in platform configuration, configure the Web OAuth client ID as serverClientId. Never include a client secret in the app.
6. Test account sign-in, scope consent, calendar selection, token refresh/expiry, revocation, offline cache and disconnect.

## Before Play Store release
1. Choose and document minSdk, targetSdk and compileSdk after plugin and Play policy review.
2. Create a release keystore locally or in a protected CI secret. Never commit keystore files or passwords.
3. Configure Play App Signing and register the Play signing SHA-1 with Google OAuth.
4. Build an Android App Bundle (AAB), not a debug APK.
5. Complete privacy policy, Data safety form, photo and calendar data disclosures, store listing, screenshots and content rating.
6. Validate on supported physical devices, including small-screen portrait and landscape, display cutouts, immersive mode, battery, photo picker, backup/restore and calendar OAuth.

## Release blockers
- OAuth client IDs and consent configuration are not yet verified.
- Final app ID and signing certificate are provisional.
- No release keystore or AAB is created.
- No physical-device QA is complete.
- Debug APK is for internal testing only.
